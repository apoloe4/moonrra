# MoonRRA 项目申报书

**项目名称与方向：** MoonRRA——面向边缘采集的多指标时序归档库；方向为 MoonBit 基础软件与可观测性。

**要解决的问题：** 网关收到的往往是多台设备交错上报的数据。设备可能晚到、重复发送或停报；如果直接对收到的值求平均，离线设备会从分母里消失。MoonRRA 让采集程序在有限内存内按事件时间整理样本，并在输出均值时一并给出实际覆盖了多少设备。

**接入方式：** Telegraf 的 `inputs.mem` 采集主机内存，`outputs.file` 按行输出秒级 JSON；MoonRRA 读取已写完的一批数据，把“测量名、数值字段、排序后的标签”作为序列标识，输出可查询的时间桶。持续运行的 MoonBit 网关可直接调用 `Collector.observe` 收样，用 `advance` 推进停报序列。两种入口共用同一份 MoonBit 核心。

**已实现的核心功能：** ① 多指标共用一个入口，各自维护迟到窗口；同一桶取事件时间最新的读数，已关闭的桶拒绝改写。序列数达到配置上限时返回拒收原因，保留已有数据。② 按明确的设备名单做跨序列查询，逐桶区分有效读数、已归档的缺测、无可用历史；达到指定上报数才给出均值。③ 提供 Telegraf 配置、乱序样本及可直接运行的回放与设备组查询示例。底层沿用 0.2.0 的多分辨率环形归档。

**三个使用场景：**

1. 主机监控：一次采集可用内存和使用率，按主机、字段分别归档，按 10 秒桶查看读数，两种单位不会混在一起。
2. 冷链网关：探头补发第 8 秒的读数时，第 17 秒的包可能已先到；窗口内两者进入各自的桶，窗口关闭后的重放有明确结果。
3. 站点巡检：三台探头中至少两台有值才发布站点均温；只有一台上报时，返回覆盖数和未知均温，避免把单台读数当成全站温度。

**拟交付与验收：** 在当前 MVP 上增加跨批次断点续采：检查点同时保存源文件位置、各序列关闭边界及未结算读数。验收时在乱序窗口内中断并重启，同一输入应与连续采集产生相同的桶和拒收统计；源文件被替换或截短时应明确报错。当前文件示例按批次独立运行，不承诺上述恢复能力，也不提供网络服务或分布式存储。

**原创与许可：** 原创 MoonBit 实现，采用 Apache-2.0。循环归档参考 RRDtool 的设计概念，采集格式参考 Telegraf 官方 JSON 文档，未移植二者源码。
